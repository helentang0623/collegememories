# 本科回忆录

一面缓慢流动的照片墙。照片从左向右流过屏幕，像一段时间；鼠标停在哪一张上，哪一张就停下来放大，其余的继续走；点开它，是这张照片背后的回忆。

纯 HTML / CSS / JavaScript，没有构建步骤，没有后端，可以直接托管在 GitHub Pages 上。

---

## 快速开始

**不要双击 `index.html` 打开**——浏览器在 `file://` 协议下不允许网页读取 `photos.json`，那样只会看到一行报错提示。

在项目目录里起一个本地服务器：

```bash
python -m http.server 8000
```

然后访问 <http://localhost:8000>。（VS Code 用户也可以装 Live Server 插件，右键 `index.html` → Open with Live Server。）

## 换成你自己的照片和文字

只需要动两个地方，不用碰任何代码。

### 1. 放照片

照片分两套，同一个文件名的图分别放在这两个文件夹里：

```
photos/web/    网页尺寸，点开某张照片看大图时用      建议长边 1400px
photos/thumb/  缩略图，照片墙上流动的那些小图用它    建议长边 500px
```

照片墙上同时有十几张图在动，如果直接用手机原图（一张就好几 MB），光是加载就要等两三秒，滑起来也会卡。所以墙上用的是 `thumb/` 里的小图，点开详情才去加载 `web/` 里的大图——整套缩略图加起来通常还不到 1MB。

手机照片直接用微信、系统相册、画图工具或任何在线压缩网站导出这两个尺寸都行。文件名要和原来一致，`photos.json` 里才不用改。

> 支持 `.jpg` `.png` `.webp` `.gif` `.svg`，浏览器能显示的都能用。
> 照片的宽高比会被自动识别，横图竖图混着放也不会被拉伸。

**懒得做两套？** 把 `photos.json` 里的 `"thumb"` 那一行整行删掉就行，照片墙会自动改用 `src`。代价是首页加载变慢。

`photos/` 根目录里的原始大图**不会被提交到 GitHub**（`.gitignore` 里已经挡掉了），它们只留在你本地备用。所以往仓库里推的只有 `web/` 和 `thumb/` 两个文件夹。

### 2. 写回忆

打开 `photos.json`，一个 `{ }` 就是一张照片：

```json
[
  {
    "id": "01",
    "src": "photos/web/01.jpg",
    "thumb": "photos/thumb/01.jpg",
    "title": "入学那天",
    "date": "2020-09",
    "text": "拖着行李箱站在校门口，太阳很大。\n\n那时候还不知道，接下来四年会发生这么多事。"
  }
]
```

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一的编号，随便起，不重复就行 |
| `src` | 大图路径，如 `photos/web/01.jpg`，点开详情时加载 |
| `thumb` | 缩略图路径，如 `photos/thumb/01.jpg`，照片墙用它。可以省略 |
| `title` | 这张照片的标题，会显示在相纸下沿和详情页 |
| `date` | 日期，建议 `2020-09` 或 `2020-09-15`；**照片墙按它排序**，所以别写错 |
| `text` | 回忆正文。写 `\n\n` 可以分段，正文会保留换行 |

几个注意点：

- 每一条的末尾用逗号分隔，**最后一条后面不要加逗号**，否则 JSON 会解析失败。
- 数组 `[ ]` 里的顺序不重要——网站会自动按 `date` 从早到晚排序，让照片墙的流动暗合时间顺序。
- 日期会显示成「2020年9月」这样的中文格式；写成别的形式（比如 `大二上`）也能显示，只是排序会不准。
- 目前的 13 条里，照片已经是你放进 `photos/` 的那些，但 `title` / `date` / `text` 还是示例文字——换成你自己的回忆就好。已有的 `id` 和图片路径别动，改文字不影响任何东西。

照片多的话，`text` 可以写很长，详情页里能滚动阅读。

## 页面上的操作

| 操作 | 效果 |
| --- | --- |
| 鼠标移到照片上 | 这一张定格并放大，其余照片继续流动 |
| 点击照片 | 打开详情，显示大图 + 标题 + 日期 + 回忆 |
| `←` `→` 或左右按钮 | 上一张 / 下一张 |
| `Esc`、点空白处、右上角 `×` | 关闭详情 |
| 浏览器「后退」 | 同样是关闭详情，不会退出整个站点 |
| 手机上轻点照片 | 直接打开详情；详情内左右滑动可翻页 |

打开某段回忆时，地址栏会变成 `……/index.html#p=02`（`p=` 后面是那条的 `id`）。所以**每一段回忆都能单独发给别人**，对方打开就直接看到那一张；用浏览器「后退」也能关掉详情，而不是跳出网站。

## 部署到 GitHub Pages（免费）

```bash
git init
git add .
git commit -m "本科回忆录"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

推送完成后，在 GitHub 仓库页面：

**Settings → Pages → Source 选 `Deploy from a branch`，Branch 选 `main` / `root`，Save。**

等一两分钟，访问 `https://<你的用户名>.github.io/<仓库名>/` 就能看到了。

> 所有路径都是相对路径，所以在 `用户名.github.io/仓库名/` 这样的子路径下也能正常加载照片。

## 想调一调

- **流动速度**：`script.js` 最上面 `CONFIG.speed`（单位：像素/秒，现在是 `26`）。
- **行数**：`CONFIG.rowsWide`（宽屏最多 3 行）、`CONFIG.rowsNarrow`（窄屏最多 2 行）。
  这是上限——照片少的时候会自动少排一行，因为一行排不满屏幕的话，同一张照片就会在屏幕上重复出现。减一行后照片更大、一行更长，正好铺满。照片够多时就会用满上限。
- **照片间距**：`CONFIG.gap` 和 `CONFIG.rowGap`。
- **照片大小**：`CONFIG.cardFill`（照片高度占行高的比例，调大照片就更大）。
- **配色**：`style.css` 最上面 `:root` 里的一组变量，改 `--paper`、`--ink`、`--accent` 就能换整体气质。
- **相纸留白**：`--pad-card`，格式是「上 右 下 左」，下沿那块留白就是写标题的地方。

想看排布日志，在网址后面加 `?debug`（例如 `http://localhost:8000/?debug`），控制台会打印每一行的位置和宽度，`<body>` 上也会挂一份 `data-debug`。

## 文件说明

```
index.html         页面结构：照片墙 + 详情覆盖层
style.css          全部样式（复古胶片暖色主题，配色集中在顶部变量里）
script.js          读取数据、排布照片、流动动画、悬停定格、详情交互
photos.json        ← 你在这里写照片和回忆
photos/            ← 原始大图放这里（不会上传，只留本地备用）
├── web/           ← 网页尺寸，点开详情时加载
└── thumb/         ← 缩略图，照片墙上流动的那些
```

进仓库的只有 `index.html`、`style.css`、`script.js`、`photos.json`、`README.md` 和 `photos/web/`、`photos/thumb/`。

## 兼容性

在 Chrome / Edge / Firefox / Safari 的近期版本上正常。已适配手机屏幕，并且会尊重系统的「减少动态效果」偏好（开启后照片墙静止，只保留悬停放大）。
